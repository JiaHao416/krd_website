  <behavior>
    - 合法 UUID、fetch 永不 resolve → status "loading"
    - fetch resolve ProductDetail → status "success"，product 為該物件；fetchProductDetail 被呼叫 1 次，參數為 (id, undefined, { signal })
    - id 為 undefined、"not-a-uuid"、"" → status "notFound"，fetchProductDetail 呼叫次數 0（it.each）
    - fetch reject new ApiError("http", "商品不存在", 404) → "notFound"；status 400 → "notFound"
    - reject new ApiError("rate_limited", "x", 429) → "error"，isRateLimited true，error 為該 ApiError
    - reject new ApiError("http", "x", 500) → "error"，isRateLimited false；reject new ApiError("network", "x") → "error"，isRateLimited false
    - reject 非 ApiError（new Error("boom")）→ "error"，error 為 ApiError（kind "invalid_response"）
    - reject new ApiError("canceled", "x") → 維持 "loading"（不進入 error）
    - rerender 切換 id A → B：第一次呼叫的 signal.aborted 為 true；A 的結果晚到（手動 resolve A 的 deferred）不會覆蓋 B；切換後立即為 "loading"（不殘留 A 的 success）；最終為 B 的 success
    - unmount 後：呼叫的 signal.aborted 為 true；之後才 resolve 也不報錯（console.error spy 未被呼叫）
    - error 後呼叫 act(() => result.current.retry()) → 先回 "loading"，fetch 被呼叫第 2 次，resolve 後為 "success"
    - StrictMode wrapper：最終 "success"；fetch 呼叫中未被 abort 的恰好 1 個（filter signal.aborted === false 的長度為 1）
  </behavior>
